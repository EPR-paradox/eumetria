# 设计问答（Design FAQ）

**这是"被追问时怎么答"的索引，不是设计文档。** 设计文档回答"要做什么"，这里回答
"为什么这么做、你怎么知道、边界在哪"。

**用法：** 面谈前通读一遍。每条的「一句话答案」是默认回答（先给结论 + 一个数字），
对方往下追问时再展开「往下问」里的层。**「边界与反例」是最值钱的一层** ——
知道自己结论的失效条件是区分"做过"和"懂了"的地方。

**纪律：** 这里每个数字都必须能在 `docs/experiments.md` 里找到出处，且由仓库内脚本产出。
答不上来的就去跑脚本，不要背。

> 内容一样，但前者读起来是工程习惯，后者读起来像准备过的答案。

## FAQ-01 你的两级拟合是按什么顺序做的？

**一句话答案：** 不是顺序解 —— 是**一次联合求解**：设计矩阵 `X = [Z(ρ,θ) | C(ξ,η)]`，
一次最小二乘，解完把系数向量按基块切开分别报告。顺序解（先场内再用残差拟合全片）有偏，
实测同一份无噪声数据：顺序解 wafer 系数误差 0.0316nm，联合解 0.0000nm。

**往下问 1：凭什么说顺序解有偏？**
两个基块在同一批采样点上**不正交** —— 把列中心化后算列间夹角，最大 |cos| = 0.173
（Zernike Z10 vs 场内 ξ）。不正交意味着谁先拟合，谁就会把对方的信号吃掉一部分。
实测两种顺序都偏：先场内 0.0316nm、先全片 0.3579nm，偏差方向取决于先后。
先场内占便宜只是因为场内基只有 6 项、自由度低，吃掉的少 —— 这是程度差异，不是对错之分。

**往下问 2：那"必须迭代到收敛"是什么意思？**
线性模型下 backfitting（交替拟合各自残差）**收敛**到联合 LS 解 —— 这是经典结论，
我也验了：迭代 200 轮到 0.0000nm，和联合求解一模一样。所以问题出在"只扫描一次"，
不是出在"分两级"。

**往下问 3：既然联合求解，为什么还要保留两层结构？**
因为**分层是可解释性的需求，不是估计器的限制**：wafer 系数给 APC / 全片校正，
场内系数给 i-HOPC / CPE，两者要分给不同的校正机制。把系数向量按列切开就能分层，
不需要用一个有偏的估计器去换"分层"。

**证据：**
```bash
.venv/bin/python experiments/q10_fit_order.py     # 五种估计器同一份数据的对照表
```
数字出处：`docs/experiments.md` → Q-10a。

**边界与反例：**
- **逐场各自拟合再对残差拟合全片是灾难**：wafer 误差 2.70nm、残差 RMS 3.82nm。
  机制是每个场的场内线性项都能吃掉本场位置处的全片局部梯度，最后拟合全片时低阶项
  已被各场以不同方式削掉（Z4 从 2.5 掉到 0.857、Z11 从 -2.2 掉到 0.499）。
  再叠上边缘场逐场二阶降秩（见 FAQ-03），这条路是双重坏。
- 结论依赖"两基块不正交"。如果先对场内基做正交化，顺序解的偏差会消失 ——
  但那时你已经在做联合求解该做的事了。

**别说：** 不要说"顺序不可颠倒"。这句话我写在设计文档里过，验算后发现是错的，
已在 §0.1 记为决策反转（D-09）—— **"我在文档里写过、后来用实验推翻"这件事本身可以讲**，
它比一个不出错的答案更能说明工作方式。

## FAQ-02 你怎么保证模型里的系数是可辨识的？

**一句话答案：** 先看设计矩阵的**秩和条件数**，再看残差。残差好看可能只是降秩后的
最小范数解在骗人 —— `np.linalg.lstsq` 在欠定系统上**不报错**。
本项目联合设计矩阵的条件数从 3.3e15 修到了 **7.6**。

**往下问 1：3.3e15 是怎么来的？**
模型的常量项写重了：Zernike 的 **Z1**（piston，恒等于 1）与场内 Cartesian 的 **(0,0)**
（也是恒等于 1）是**完全相同的两列**，联合矩阵因此降秩。两个基单独看条件数都很好
（Zw 4.7、Cf 6.6），叠起来才炸 —— 所以"每个基单独没问题"推不出"合起来没问题"。

**往下问 2：那常量该归谁？**
归 wafer-level 的 **Tx = Z1**（§3.1.1 的线性 6 参数表里本来就写着 Tx 对应 Z1）。
场内基去掉常数项后，条件数 **3.3e15 → 7.6**，而解不变（仍是 0.0000nm 恢复到真值）。
物理上也说得通：全片整体平移，和"每个场都有同样大小的常量偏移"，本来就是同一件事。

**往下问 3：条件数多大算坏？**
项目约定 >1e6 写警告（§9.3）。重点不是阈值本身，而是**条件数告警要能用**：
它如果被一个模型设计缺陷长期占着，真正需要它报数据问题时就没人看了。

**证据：**
```bash
.venv/bin/python experiments/q10_fit_order.py     # 输出里含"完全相同的列"诊断与条件数对比
```

**边界与反例：**
- 这个混叠只在**场内基跨场共享系数**时出现。若 CPE 是逐场独立一套系数，每场一个常量，
  就不与 Z1 混叠 —— 但那时点数问题登场（FAQ-03）。
- 病态不等于必须上正则化。**先找混叠原因**（有没有重复列、有没有物理上不可分的两项），
  再去谈岭回归。上来就加正则化会把"模型写错了"当成"数据不够"来处理。
- 秩/条件数检查是**显式**写在代码里的，不依赖求解器报错。

## FAQ-03 边缘场点数不足，CPE 要不要降阶？

**一句话答案：** 不要逐场降阶，而是把**全局 CPE 阶数降到最差场能支持的那一档**。
默认采样方案实测：一阶（3 项）在 5 点的边缘场上条件数 2.95，全部可用；
二阶（6 项）在 5 点上 **rank 5 < 6，不可辨识**。所以默认方案的 CPE 上限就是一阶。

**往下问 1：为什么不能逐场降阶？**
三条，一条比一条要紧：
1. CPE 的判据是**跨场系数变异**，各场阶数不同则系数不在同一空间，比较作废；
2. 扫描机施加的是**同一套**模型 —— 物理上不存在"第 60 场用一阶、第 6 场用二阶"这种校正；
3. 最阴的一条：降阶会把该场残差系统性放大，而残差正是"不可校正 residual"的估计 ——
   你会把自己的降阶误读成"这片工艺不可校正"，**错误会伪装成结论**。

**往下问 2：那正确做法是什么？**
优先级：① 全局统一档位（默认方案 → 一阶）；② 在**采样层**解决，不是在拟合层 ——
给边缘场自适应布置 mark（往可用区内收），或把边缘场排除出 CPE 拟合并在
`identifiability.warnings` 里显式列出；③ 非要保二阶就用正则化/先验，但要明说引入了偏差。

**往下问 3：为什么平均点数够不算够？**
CPE 是逐场一套系数，约束是**每个场各自**的点数 ≥ 该场参数数。25 场平均 7.5 点看着很宽裕，
但 4 个边缘场只有 5 点 —— 平均数是这里最容易骗人的统计量。

**证据：**
```bash
.venv/bin/python experiments/q10_cpe_order.py     # 逐场的秩与条件数
```

**边界与反例：**
- 满点场的二阶条件数 6.61 是这个 mark 布局的**地板**：8 个 scribe-line mark 在 ξ=±0.769、
  η=±0.818，只覆盖场内归一化面积的 0.63×0.63，外圈 23%/18% 是靠外推。想更低要换布局，
  不是换求解器。
- `lstsq` 在 5 点 6 项**不报错**，会给一个物理上无意义的最小范数解。守卫必须显式。

## FAQ-04 业界不是先场间再场内吗？

**一句话答案：** 是，而且它成立的理由**不是"顺序"，是"聚合"**。阶段 1 把每个场压成几个量
（平移/旋转/倍率），阶段 2 拿这些量对**场中心坐标**回归 —— 两个阶段用的是不同自变量，
不是把同一批残差再拟合一遍。但它有个前提：**阶段 1 的线性项不能丢。**

**往下问 1：丢了会怎样？**
实测：场内线性项 (1,0) 真值 1.2nm，被恢复成 0.000、全场残差 RMS 1.0nm。原因是共享的
场内线性指纹被每场自己的线性项吃掉了，丢掉了就再也回不来。所以"先用场内坐标拟合低阶和
高阶"这句要小心 —— 如果低阶是在逐场那一层拟合的，它就不会再出现在后面的共享拟合里。

**往下问 2：那正确的两级是什么样的？**
对每场线性项做**均值/变差分解**：
- **均值**（跨场不变的部分）= 共享的场内低阶指纹 → 归 i-HOPC / CPE
- **随场中心变化的变差** = wafer 低阶（它就是全片指纹在单场内的局部梯度）→ 归 APC

这是 between-field / within-field 的正式分法，也解释了为什么两级的语义是对的。

**往下问 3：既然两级对，为什么不干脆用两级、非要联合求解？**
因为两者成立的条件不同。**机器上确实是两套控制环**（APC 与 i-HOPC/CPE，更新率和参数集都不同），
模型器要产出两套参数，分两级是自然的；而且当 wafer 级只用对准 mark 或场中心专用 mark 测量时，
两阶段吃的**是不同数据**，根本没有"联合"可言。但在我们这套仿真里两阶段吃的是**同一批 188 点**，
所以联合求解更优（0.0000nm vs 0.2354nm）—— **聚合在这里是纯粹的统计效率损失**。

**往下问 4：聚合的代价具体是多少？**
场间回归只有"场数"个观测（25 个，不是 188），所以高阶 wafer 项受损：Z4 误差 0.073nm、
Z11 误差 0.158nm —— 与等效 TMU 0.0707nm 同量级；而低阶（Z1/Z2/Z3）恢复得很好，
因为 25 个场中心观测对 3 个低阶参数绰绰有余。**业界的做法正好用在它够用的地方：低阶平移旋转倍率。**

**证据：**
```bash
.venv/bin/python experiments/q10c_lumped_two_stage.py
```
数字出处：`docs/experiments.md` → Q-10c。

**边界与反例：**
- 混叠不可判定：把场内常数项设成 0.7nm（真值 Z1 仍是 2.0），场中心回归给出的"Z1"是 2.950，
  而两组参数给出**完全相同**的预测、残差都 0.0000nm。→ 常量归谁只能靠**约定**，不能靠估计顺序。
- "池化 + 一次扫描"在含低阶真值时直接崩（Z1 从 2.000 变 -0.001、(2,0) 从 0.5 涨到 2.620），
  根因是**幂基偶次列（ξ²、η²）在采样点集上均值不为零**，会把常量吸走。
  → 这也是 U-07（改用 Legendre）的实证理由：Legendre 的列按构造零均值。

**别说：** 不要说"业界是先场间再场内，所以顺序无所谓"；也不要把"顺序"当成主要区别 ——
区别在**聚合**（自变量换了）和**逐场量有没有做均值/变差分解**。
